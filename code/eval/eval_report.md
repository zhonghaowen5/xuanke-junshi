## 二、本轮升级：从单专业到 12 个专业

知识库从 1 份培养方案（28 切片）扩展到 **12 份**（375 切片）：

- 普通专业：人工智能、智能科学与技术、机器人工程、数据科学与大数据技术
- 英才班：数据科学与大数据技术英才班、智能科学与技术新工科英才班、智能机器人英才班
- 联合培养：数据科学与大数据技术+经济学联合培养
- 微专业：HarmonyOS 技术与应用、具身智能机器人应用开发、智能机器人设计与开发、行业大数据挖掘及应用

## 三、多专业带来的新问题与修复（重要技术点）

多专业知识库混在一起后，出现了三类典型的「串味」问题，全部修复：

### 1. 跨专业冒答（最严重）
问「人工智能专业毕业最低总学分」，系统用联合培养的 166 学分冒答（正确答案 160）。

**修复：专业路由（第 0 层防护）**
- 从 PDF 文件名提取已收录专业名，对问题做**最长匹配**；
- 命中专业后，检索时直接用 `source` 过滤，**只在该专业的切片内检索**；
- 微专业允许省略「（微专业）」后缀匹配；
- 检索 query 会把专业名剔除，避免长专业名稀释真正的问题语义。

### 2. 资料无来源标注，模型无法判断专业归属
原来给模型的资料只标「章节 + 页码」，模型不知道每条资料属于哪个专业。

**修复**：资料头改为「来源（PDF 文件名，即专业名）· 章节 · 页码」，并在 SYSTEM_PROMPT 新增规则 7：问题指明专业时，只能引用来源一致的资料。

### 3. 关键条款被切片稀释
「3、毕业学分要求 必修136学分，选修24学分，总学分：160学分」这类关键句子原来埋在其他章节的切片尾部，多专业竞争下检索不到。

**修复**：`ingest.py` 章节识别新增 `^\d+、` 和 `^\(\d+\)` 两个模式，让「3、毕业学分要求」这类小节独立成块，切片从 327 → 375，检索命中率显著提升。

### 4. 误判修复：正确答案 + 谨慎尾巴被整题判错
模型有时先给出完全正确的内容、结尾再补一句「资料不足，无法回答更具体的信息」，被误判为整题拒答。

**修复**：`run_eval.py` 事实题评测改为**无论是否标记拒答都交给裁判模型判断**，以实际内容为准。

### 5. 题目本身的错误
- 第 43 题「专业核心课一共有几门」：联合培养方案中**不存在**「专业核心课」模块（实际模块为专业基础课、专业方向课等），系统的拒答才是正确行为 → 重分类为拒答题。
- 全部 102 道事实题补上专业限定「（数据科学与大数据技术+经济学联合培养专业）」，保证多专业库下评测的公平性。
- 新增 12 道多专业事实题（覆盖全部 12 个专业的毕业总学分）。
